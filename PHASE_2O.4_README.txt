ManaChaiLeasing Phase 2O.4
Controlled Pawn Ticket Editing and Audit Log
Version 0.3.8

สิ่งที่เพิ่ม
1. เพิ่มปุ่ม "แก้ไขข้อมูล" ในหน้ารายละเอียดตั๋วจำนำ
2. เปิดให้แก้ข้อมูลลูกค้าและข้อมูลสินค้าเมื่อพบการพิมพ์ผิด
3. มีช่องเหตุผลการแก้ไขแบบไม่บังคับ หากเว้นว่างจะแสดงว่าไม่ได้ระบุ
4. แสดงหน้าต่างยืนยันก่อนบันทึก
5. เก็บประวัติวันเวลา Windows user ชื่อเครื่อง เหตุผล และค่าก่อน–หลัง
6. แสดงประวัติการแก้ไขทั้งหมดในหน้ารายละเอียดตั๋ว
7. Refresh หน้ารายละเอียดทันทีหลังแก้ไขสำเร็จ
8. เรียก Auto Backup หลังบันทึกการแก้ไข

ข้อมูลที่แก้ไขได้
- ชื่อและนามสกุลลูกค้า
- เลขบัตรประชาชน โดยตรวจรูปแบบ 13 หลักและป้องกันเลขซ้ำ
- อายุ โทรศัพท์ และที่อยู่
- ประเภทหลัก ประเภทสินค้า ยี่ห้อ รุ่น ความจุ / ขนาด และสี
- IMEI / Serial อุปกรณ์ สภาพ / ตำหนิ
- สเปก รายละเอียดอื่น รายละเอียดสินค้าสรุป และหมายเหตุตั๋ว

ข้อมูลที่ล็อก ไม่อนุญาตให้แก้จากหน้านี้
- เลขตั๋ว
- วันที่รับจำนำ
- เงินต้น
- อัตราดอกเบี้ยและระยะเวลาต่อรอบ
- สถานะตั๋ว
- ประวัติเงินเข้า / ออก
- รายการต่อดอก ไถ่ถอน และจำหน่าย

ข้อควรทราบ
- ข้อมูลลูกค้าเป็นข้อมูลกลางที่ใช้ร่วมกันทุกตั๋วของลูกค้าคนนั้น
- หากแก้ชื่อ เลขบัตร อายุ โทรศัพท์ หรือที่อยู่ จะมีผลกับทุกตั๋วของลูกค้ารายนั้น
- หากข้อมูลทางการเงินผิด ไม่ควรแก้ตัวเลขย้อนหลัง ให้ใช้กระบวนการยกเลิกและสร้างรายการใหม่
- ประวัติการแก้ไขที่บันทึกแล้วไม่เปิดให้แก้หรือลบจากหน้าจอโปรแกรม

Database Migration
- เพิ่มตาราง PawnTicketEditAudits
- โปรแกรมจะ Migration อัตโนมัติเมื่อเปิดเวอร์ชัน 0.3.8 ครั้งแรก
- ข้อมูลตั๋ว ลูกค้า และรายการเงินเดิมไม่ถูกลบหรือเขียนทับโดย Migration
- ก่อนนำไปอัปเดตเครื่องลูกค้า ควรสร้าง Backup ฐานข้อมูลล่าสุดไว้ก่อนเสมอ

UAT
1. สำรองฐานข้อมูลทดสอบก่อนเริ่ม
2. เปิดตั๋วจากหน้าค้นหารายการ รายการวันนี้ หรือประวัติลูกค้าจากบัตร
3. ตรวจว่ามีปุ่ม "แก้ไขข้อมูล" ในหน้ารายละเอียดตั๋ว
4. เปิดหน้าแก้ไข ตรวจว่ามองเห็นข้อมูลเดิมครบ
5. ตรวจว่าเลขตั๋ว วันที่ เงินต้น ดอกเบี้ย สถานะ และประวัติเงินไม่มีช่องให้แก้
6. แก้ข้อมูลสินค้าอย่างน้อย 1 ช่อง แล้วบันทึก โดยจะกรอกหรือเว้นเหตุผลก็ได้
7. ตรวจว่าหน้ารายละเอียด Refresh และแสดงค่าใหม่
8. เลื่อนลงด้านล่าง ตรวจประวัติการแก้ไขว่ามีค่าก่อน–หลัง เหตุผล วันเวลา ผู้ใช้ และชื่อเครื่อง
9. ปิดแล้วเปิดตั๋วใหม่ ตรวจว่าค่าใหม่และ Audit Log ยังอยู่
10. ทดลองกดบันทึกโดยไม่เปลี่ยนข้อมูล ต้องถูกปฏิเสธ
11. ทดลองไม่ระบุเหตุผล ต้องบันทึกได้ และ Audit Log ต้องแสดงว่าไม่ได้ระบุ
12. ทดลองกรอกเลขบัตรไม่ครบ 13 หลัก ต้องถูกปฏิเสธ
13. หากมีลูกค้าอย่างน้อย 2 คน ทดลองใช้เลขบัตรของอีกคน ต้องถูกปฏิเสธ
14. แก้โทรศัพท์ลูกค้าที่มีหลายตั๋ว แล้วเปิดตั๋วอื่นของลูกค้าคนเดิม ตรวจว่าข้อมูลเปลี่ยนตาม
15. ตรวจว่า Auto Backup ยังทำงานหลังบันทึก
